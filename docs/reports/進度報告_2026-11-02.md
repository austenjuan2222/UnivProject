日期：2026-11-02
程式：PR #5（README 新增一節「依課程講義補強」）。上一份：`進度報告_2026-11-01_第三輪.md`（DP 與 VD 數量、預測距離的完整結果）。
方向：依 Austen 10/30 傳的課程講義（IoT 架構、IoT 安全），測試聯邦學習在攻擊與斷線時能不能撐住。

## 1. 一句話結論

**HMAC 能擋住網路上的竄改，而且不影響準確度。** 但如果 VD 本身被入侵，就要改用中位數或截尾平均來聚合，用 FedAvg 時誤差會暴增到 251 km/h；入侵達 10/32 個 VD 時截尾平均失效，中位數全域略輸 naive，伺服器端裁剪仍贏 naive（但平時要多付 0.09），兩者合用最好；到 14/32（44%）時全域模型都輸 naive，只剩本地微調後仍贏。**全部防禦一起開**時，就算同時有 3 個 VD 被入侵、10% 竄改、10% 斷線，全域 2.295 仍贏 naive；256 個 VD、26 個被入侵時也一樣（2.304，好 8.5%）。每輪有 30% 的 VD 斷線時，訓練照常完成，準確度幾乎不變。把上傳量化成 4 位元，流量小 7.8 倍（0.79 KB／輪），準確度不變。

**全部防禦一起開**（VD Ed25519 簽章 + 4 位元上傳 + 中位數聚合 + 伺服器裁剪 C=0.2；同設定，3 seed）：

| 情境 | 全域 MAE | 本地微調後 |
|---|---|---|
| 沒有攻擊 | 2.275（好 6.3%） | 2.161 |
| 3 個 VD 被入侵 + 10% 上傳被竄改 + 10% 斷線 | **2.295（好 5.5%）** | **2.164** |

三種攻擊同時發生時仍贏 naive，被竄改的 63 份更新全部被擋下，每輪每個 VD 只上傳 0.79 KB。全開的代價主要來自伺服器裁剪（沒攻擊時 2.275 vs 一般設定 2.183）。資料：`s32_full_{noatk,atk3}.csv`。

**擴大到 256 個 VD**（同樣 DP σ=1.1、3 seed，naive 2.519；全部防禦 = VD Ed25519 簽章 + 4 位元上傳 + 中位數 + 伺服器裁剪 C=0.2）：

| 情境 | 防禦 | 全域 MAE（比 naive 好） | 本地微調後（比 naive 好） |
|---|---|---|---|
| 26 個 VD（10%）被入侵 | 無（FedAvg） | **約 368（156～624，完全失效）** | 41.7 |
| 沒有攻擊 | 全部防禦 | 2.279（9.5%） | 2.192（13.0%） |
| 26 個 VD 被入侵 + 10% 竄改 + 10% 斷線 | 全部防禦 | **2.304（8.5%）** | **2.199（12.7%）** |

VD 多時，全部防禦的效果和 32 個 VD 一致：三種攻擊同時發生，全域只比沒攻擊時差 0.025。資料：`results/night4/security_256/s256_*.csv`（數字已重算核對）。

> 註：伺服器裁剪借用 client-level DP 的裁剪機制，但只加 σ=0.01 的雜訊，所以 CSV 的 `final_epsilon` 欄位會顯示約 110111，代表這一層**不提供** client-level 隱私，只用來限制被入侵 VD 的影響。隱私保證仍是 record-level DP σ=1.1（ε 約 2.37），中位數聚合、量化都是後處理，不改變這個 ε。「平常代價 0.08」是跟 night3 舊程式的結果比，尚未用同一版程式補跑無防禦對照組。

**解讀**：
- **HMAC 的代價幾乎是零**：和沒有安全檢查的舊程式只差 0.0001。
- **HMAC 與被入侵的 VD 是兩種不同的威脅。** HMAC 只能確認上傳在網路上沒被改過。如果 VD 本身被入侵，送出的雖然是合法簽章的壞更新，HMAC 擋不住，要靠穩健聚合。
- **穩健聚合的代價很小。** 沒有攻擊時，中位數 2.189、截尾平均 2.186，和 FedAvg 的 2.183 差不多。受攻擊時兩者都只差約 0.05，仍比 naive 好約 8%。
- **中位數比截尾平均耐打**：被入侵的 VD 超過截掉的比例（10/32）時截尾平均完全失效；中位數在 10/32 時全域只略輸 naive，微調後 2.160 仍比 naive 好 11%。
- **伺服器端裁剪是另一種取捨**：沒有攻擊時就要多付約 0.09（2.269 vs 2.183），但 10/32 個 VD 被入侵時全域 2.395 仍贏 naive，比中位數的 2.469 穩；微調後則是中位數較好（2.160 vs 2.209）。資料：`s32_clip_noatk.csv`、`s32_atk{3,10}_clip.csv`。
- **防禦的極限**：10/32 個 VD 被入侵時，裁剪加中位數一起用最好（全域 2.371）。到 14/32（44%）時，所有方法的全域模型都輸 naive；但本地微調後仍贏 naive，中位數 2.190、裁剪 2.349。也就是被入侵的 VD 接近一半時，共用模型已經不可信，要靠各 VD 自己微調。資料：`s32_atk10_clipmed.csv`、`s32_atk14_{clip,median}.csv`。
- **不可否認性與可歸責性**：改用 VD 自己的 Ed25519 簽章上傳後，伺服器只有公鑰，偽造不了 VD 的簽章，準確度和 HMAC 一樣。每個 run 寫出稽核紀錄 `audit.jsonl`（約 640 行），記錄輪次、VD、內容雜湊、簽章，以及這份更新有沒有被採用，出事時可以追到是哪個 VD。
- **安全聚合**：各 VD 用 X25519 交換金鑰後加上成對遮罩，伺服器只算得出所有 VD 更新的加總，看不到單一 VD 的更新。準確度和不加時只差 0.0001，遮罩全部抵銷。代價是每輪上傳從 6.1 KB 變成 12.3 KB（遮罩用 float64）。限制是不能和中位數聚合或 client-level DP 同時用，也不容許 VD 中途斷線。
- **斷線不影響訓練**：每輪 30% VD 沒回覆時，全域模型 2.194，比正常只差 0.011。

資料：`results/night4/security_32/s32_*.csv`（數字已重算核對）。對照 IoT 講義五個問題與 CIA 要求的完整表格在 PR #5 的 README「依課程講義補強」一節。

## 3. 安全審查

用 `security-review` 檢查新程式，找到一個高風險問題：第一版讓所有 VD 從同一個設定值推導金鑰，任何一台 VD 都能反推別台 VD 的金鑰和伺服器私鑰，簽章形同虛設。已改成每個 VD 一把隨機金鑰（`keys/vd-<編號>.key`，不進 git），伺服器另用 Ed25519 私鑰簽全域模型，系統裡沒有共用的主密鑰。HMAC 用標準的 HMAC-SHA256，不是講義上的 H(K||M)，因為後者有長度延伸攻擊的問題。

## 4. 限制

- 大部分實驗是 32 個 VD、3 seed；256 個 VD 只測了全部防禦與無防禦兩種。安全聚合和穩健聚合目前不能同時開。攻擊方式測了反向放大 10 倍、隨機雜訊、串通小幅偏移、竄改與重送，被入侵 VD 數測到 3、6、10、14 個。
- 截尾平均能承受的被入侵 VD 數量取決於截掉的比例，10/32 時已超過上限。

## 補充（2026-11-03）：依講義再補十項

1. **TLS 與 VD 裝置認證**：改用 Flower 部署模式實際走 gRPC over TLS，8 個 VD 訓練 3 輪完成（MAE 2.916，naive 3.008）。沒註冊的假 VD 被拒絕，不用 TLS 的明文連線連不上。
2. **串通小幅偏移攻擊**（32 VD、3 seeds）：攻擊者把更新量控制在正常範圍內、同一輪往同一方向偏。傷害很小，最壞多 0.05、仍贏 naive 4%。但「裁剪＋中位數」這組反而受傷最大（10 個 VD 時 +0.052，三個 seed 都變差），說明穩健聚合擋不住小而一致的偏移，要靠跨輪行為偵測。
3. **Edge 資源**：桌機上 256 VD 同時模擬，每輪最慢的 VD 中位數 0.60 秒。單獨量一台 VD：訓練峰值 425 MB，其中約 365 MB 是 PyTorch／Opacus 框架本身，模型只有 6.1 KB，每輪 0.16 秒。
4. **串通偵測**：跨輪比對 VD 之間更新的相似度（概念同 FoolsGold）。FedAvg 下第 2～5 輪就抓到所有串通者、沒有誤判，但準確度沒有改善。「裁剪＋中位數」下預設門檻（z=3）抓不到；放寬到 z=2 抓得到，誠實 VD 的 MAE 改善約 0.04，但偶爾會誤判 1～2 台。
5. **撤銷（RFID 標籤撤銷）**：撤銷某台 VD 的註冊後，它現有的連線立刻被切斷，用原本的金鑰也連不回來。
6. **資安運算成本**：簽章和 HMAC 加起來不到每輪訓練時間的 0.1%，上傳只多 32～64 位元組。安全聚合每輪約 3 ms（訓練的 2%），但上傳量加倍且不能壓縮，在 LPWAN 上要取捨。
7. **部署可用性**：TLS 部署原本第 1 輪會少 1～3 台 VD。原因是 8 台擠在同一台電腦：共用資料夾同時解壓衝突，以及分頁檔不足。改成每台 VD 用自己的資料夾後，連跑 3 次每輪都 8／8。

8. **LPWAN 空中時間**：用 Semtech 公式算 LoRaWAN。訊號差的 VD（SF12、1% 工作週期）不壓縮時一輪要等約 9.6 小時；4 位元縮到 1.3 小時，一天更新一次模型可行。訊號好（SF7）時 4 位元每輪 4 包、1.4 秒。台灣 AS923 每包限 400 ms，訊號差的 VD 改用 NB-IoT 較合適。
9. **防重送**：模擬中間人把 25% 上傳換成該 VD 上一輪的整份訊息。有 HMAC 時全部被拒絕（每個 seed 146～164 份）；沒驗證時全被聚合，但只落後一輪，傷害不顯著（+0.005）。
10. **安全聚合容許斷線**：原本少一台 VD 整輪作廢；現在在線 VD 交出和斷線 VD 之間的遮罩種子，伺服器扣掉後照常聚合。32 VD、10% 斷線、3 seeds，準確度和一般 FedAvg 差不到 0.0001。安全檢查後補上 VD 端與伺服器端的限制；仍是簡化版，沒有 SecAgg+ 的雙重遮罩。

程式與表格在 GitHub 分支 `claude/lecture-tls-baseline` 的 README。
