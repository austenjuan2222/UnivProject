## 1. 一句話

用高公局國道 VD 的真實車速資料做「聯邦學習＋差分隱私」的車速預測：每個 VD 只在本地訓練，原始資料不離開 VD。
在這個基礎上，依課程講義（IoT 架構、IoT 安全、TLS／MAC、RFID、LPWAN）把系統補成「可以抵抗攻擊、可以部署在 Edge」的版本，
每一項都用實驗驗證（3 個 seed、同版程式的對照組、報配對差值）。

## 3. 準確度與隱私（主線結果）

naive 基準＝「下一個 5 分鐘車速＝現在的車速」。MAE 單位 km/h。

| 結論 | 證據 |
|---|---|
| DP 幾乎不花準確度 | 8 VD：DP σ=1.1 微調後 2.669，無 DP 2.670；128 VD：只裁剪不加噪 2.090 vs DP 2.097（雜訊代價 < 0.01） |
| DP 在長預測反而更準 | 30 分鐘、所有 VD 數（8～256）微調後 DP 都顯著好於無 DP；256 VD 無 DP 不裁剪會發散 |
| 時段特徵是最可靠的改進 | 4 週資料 DP σ=1.1 2.719 → 2.685（5/5 seed，p<0.001），ε 不變 |
| 保護整個 VD 需要更多 VD | client-level DP σ=4：8 VD 輸 naive 27%，32 VD 贏 4.9%，128 VD 贏 9.5% |
| ε < 1 也可行 | 256 VD 每輪抽 25%、整個 VD 的 ε=0.79，全域贏 naive 8.8%、微調後 13.1% |
| 成員推論攻擊對本模型無效 | AUC 0.515（無 DP 也一樣），隱私保證以 ε 為準 |

沒有幫助、已排除的：GRU、相鄰 VD 車速、昨天同一時刻、週末旗標、自適應裁剪、更大模型等。

## 4. 依講義的資安與 IoT 補強（32 VD、DP σ=1.1、3 seed，naive 2.429，無攻擊 2.183）

| 講義主題 | 做了什麼 | 結果 |
|---|---|---|
| MAC（完整性） | 每台 VD 自己的金鑰算 HMAC-SHA256，輪次簽進去 | 25% 竄改：沒驗證 2.465（輸 naive），有驗證 2.186，全部擋下 |
| 防重送 | 把上一輪的舊訊息再送一次 | HMAC 擋下全部 146～164 份；舊訊息傷害本來就小（+0.005，不顯著） |
| 數位簽章 | 伺服器 Ed25519 簽全域模型；VD 可選 Ed25519 簽更新（不可否認）＋稽核紀錄 | 準確度不變，每份 64 bytes |
| 裝置被入侵 | 穩健聚合（中位數、截尾平均、伺服器裁剪） | 3 台反向放大：FedAvg 壞到 251，中位數 2.232；撐到約 1/3 被入侵 |
| 全部防禦一起開 | 3 台入侵＋10% 竄改＋10% 斷線 | 2.295，仍贏 naive 5.5%；256 VD 時 2.305 |
| 隱蔽串通攻擊 | 多台同方向小偏移；跨輪相似度偵測（FoolsGold 概念） | FedAvg 下全部抓到、無誤判；裁剪＋中位數時要把門檻放寬到 z=2 才抓到（偶有誤判） |
| 針對性攻擊 | 「隱藏壅塞」：3 台把塞車標籤改高 30 km/h | 全域 MAE 只多 0.03～0.19，但塞車時段偏差 +3.6 → +9.0 km/h；**只看整體 MAE 會漏掉** |
| TLS、RFID 偽造標籤、撤銷 | Flower 部署模式：TLS＋SuperNode 公鑰註冊 | 假 VD、明文連線、撤銷後的 VD 都被拒；8／8 VD 正常訓練 |
| 機密性（伺服器不可信） | 安全聚合（X25519 成對遮罩）＋斷線復原 | 準確度不變；10% 斷線時每輪都復原成功 |
| 可用性 | 每輪 30% VD 斷線 | 2.194，照常完成 |
| Edge 資源 | 量單台 VD 的記憶體、時間、資安運算 | 峰值 425 MB（框架佔 365 MB）、每輪 0.16 秒；簽章＋HMAC < 0.1% 訓練時間，安全聚合約 2% |
| LPWAN | 4 位元量化上傳＋LoRa 空中時間公式 | 上傳 6.1 → 0.79 KB 準確度不變；SF12 每輪從 9.6 小時降到 1.3 小時；台灣 AS923 建議訊號差的 VD 用 NB-IoT |

## 5. 最後一組實驗（隱藏壅塞 × 串通偵測）

問題：前面做的「跨輪串通偵測」能不能抓到「隱藏壅塞」的攻擊者？

答案：**抓不到。** FedAvg、裁剪＋中位數，門檻 z=3 和 z=2，各 3 個 seed，三個攻擊者（VD 29～31）一次都沒被標記。
z=2 標記到的 VD 19、20、24 在沒有攻擊時也會被標記，是誤判。塞車時段偏差和不開偵測時一樣（FedAvg +9.0、裁剪＋中位數 +5.1 km/h）。

原因：串通偵測看的是「多台 VD 的更新方向是否一直很像」。串通攻擊共用同一個偏移方向，所以抓得到。
隱藏壅塞的攻擊者各用自己路段的資料訓練，只是標籤被改高，更新方向和誠實 VD 一樣分散，所以抓不到。

意義：**偵測方法要對應攻擊的特徵**，沒有一個防禦能擋所有攻擊。這可以當報告裡「防禦的極限」的例子。
要擋這種攻擊，伺服器得拿一小份公開的塞車資料檢查每份更新。但這樣伺服器必須看得到個別更新，又和安全聚合衝突。這部分列為後續。

## 6. 用到的工具

- Flower 1.26、PyTorch、Opacus（DP-SGD）、cryptography（HMAC、Ed25519、X25519）。
- `security-review`：檢查金鑰設計（抓到第一版所有 VD 共用主密鑰的嚴重問題）、安全聚合復原的惡意伺服器情境。
- graphify：建專案程式地圖，找相關程式時不用整個 repo 掃。
- markitdown：讀課程講義 PDF／PPT。
- `lecture-optimize` skill：把「依講義持續優化」的做法寫成固定流程。

## 7. 限制（報告時要誠實講）

- 資料只有 2024 年 3 月的 4 週、國道 1 號；結論在其他路段與季節要再驗證。
- ε 是 record-level（保護單筆 5 分鐘紀錄），相鄰時間高度相關；loss 等診斷值沒有加噪，不在保證內。
- 安全聚合是簡化版：遮罩用 PCG64 和浮點數（非密碼學等級），沒有雙重遮罩，伺服器仍可謊稱某台斷線。
- 穩健聚合和安全聚合不能同時開（伺服器看不到個別更新就無法取中位數）。
- 所有攻擊實驗都是模擬；TLS 部署是同一台電腦上的 8 個行程。
