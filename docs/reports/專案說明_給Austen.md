## 1. 一句話說明

用**台灣國道 VD（車輛偵測器）的真實車速資料**，訓練一個「用過去 1 小時車速預測下 5 分鐘車速」的小模型。
訓練方式是**聯邦學習**（資料留在各偵測器，不集中），並在每個偵測器本地加上**差分隱私（DP）**。
最後比較：「加隱私保護」會讓預測變差多少、換到多少隱私（ε）。
訓練完後，每個偵測器還可以用自己的資料把模型**再微調幾步**（個人化），讓模型更貼近自己那段路。

**目前最重要的發現（第三輪）**：VD 越多，DP 的代價越小；256 個 VD 時所有 DP 設定在 5／15／30 分鐘都比 naive 準。和「無 DP 但也加梯度裁剪」的公平基準比，微調後的 DP 在 15、30 分鐘反而更準，VD 越少差距越大。

## 2. 三個核心概念（白話）

| 概念 | 白話解釋 | 在本專案對應 |
|---|---|---|
| 聯邦學習（FL） | 每個參與者在自己電腦上訓練，只把「模型參數」交給伺服器平均，原始資料不外流 | 1 個 VD = 1 個 client；伺服器做 FedAvg（依資料量加權平均） |
| 差分隱私（DP-SGD） | 訓練時把每筆資料對模型的影響「剪短」（裁剪），再加隨機雜訊，讓別人很難從模型判斷某一筆資料有沒有被拿來訓練 | Opacus 套件；裁剪上限 C=1.0、雜訊倍率 σ（0.8 / 1.1 / 1.5 / 3） |
| 隱私預算 ε | 數字越小越隱私。訓練越多輪，ε 越累積越大 | `privacy.py` 跨輪次累加，寫進 `metrics.csv` 的 `epsilon_max` |

用到的框架：**Flower**（聯邦學習模擬，1.26 版 Message API）、**PyTorch**（模型）、**Opacus**（DP-SGD）。

## 5. 每個程式在做什麼、為什麼這樣設計

### 5.1 資料階段

**`scripts/download_vd.py` — 下載原始資料**
- 做什麼：依日期抓 `https://tisvcloud.freeway.gov.tw/history/motc20/VD/YYYYMMDD/VDLive_HHMM.xml.gz`（每分鐘一檔），邊下載邊解析，只存需要的欄位成 `data/raw/vd_minute_YYYYMMDD.csv`。
- 為什麼：原始 XML 很大，只存 CSV 省空間；只保留 VDID 含 `N1`（國道 1 號）的偵測器。每天完成會留 `.done` 標記，中斷後重跑會跳過已完成日期；單日缺檔太多（> 30 分鐘）不標記完成，方便補抓。
- 同時下載數預設 2，避免對政府網站造成負擔。

**`vd_parse.py` — 解析 XML**（被下載程式呼叫）
- 做什麼：把一個 VD 的多個車道合併成一個車速。
- 規則：車速 ≤0 或 ≥200（含錯誤碼 -99）、或狀態碼 ≠0 視為無效；VD 車速 = 有效車道的**流量加權平均**（車多的車道比較有代表性）。

**`scripts/preprocess_vd.py` + `vd_preprocess.py` — 前處理**
- 做什麼：每分鐘 → 每 5 分鐘平均；一個 5 分鐘桶至少 3 分鐘有效才算數；連續 ≤15 分鐘的缺口用線性內插補，更長的缺口留空；挑出有效率 ≥80% 中最完整的 8 個 VD，各存一個 CSV，並寫 `manifest.json`（哪個 client 編號對應哪個 VD、資料期間、篩選條件）。
- 為什麼：5 分鐘是交通預測常用粒度，雜訊較少；長缺口不亂補，避免造假資料；`manifest.json` 讓之後每一步都知道有幾個 client、誰是誰，確保可重現。
- `-M-` 的 pattern 是只取**主線**，排除匝道（匝道車速行為不同）。

**`scripts/make_synthetic_vd.py` — 合成資料（只供測試）**
- 產生格式相同的假資料，讓沒有網路時也能測試整個流程。**結果不能寫進報告。**

### 5.2 訓練階段（Flower 聯邦學習）

**`data.py` — 每個 client 的資料準備**
- 讀自己那個 VD 的 CSV → 依時間**前 80% 訓練、後 20% 測試**（不打亂，避免用未來資料預測過去）→ 只用訓練段的平均與標準差做標準化（避免偷看測試資料）→ 切成「過去 12 筆 → 下一筆」的滑動視窗，含空值的視窗丟掉。
- **時段特徵（第三輪新增，PR #3，預設開啟）**：每個視窗前面再加上「要預測的那個時間點」在一天中的位置，用 sin、cos 兩個數字表示（`calendar = "tod"`）。
  為什麼：各 VD 的尖峰時段不同，只看過去 1 小時車速，模型不知道「接下來是不是要進入尖峰」。時間是從時間戳記算的，不是新的私有資料，ε 不變。4 週資料 5 seed：DP σ=1.1 微調後 2.719 → 2.684（5/5 seed 變好；兩週資料 2.665 → 2.642；32 個 VD 2.129 → 2.116、30 分鐘 3.322 → 3.230）（配對 t 檢定 p=0.0009，效果量 d_z −3.9；有時段特徵時 DP σ=1.1 和無 DP 差 −0.009，p=0.44，不顯著，`scripts/seed_stats.py`）；全域模型則沒有改善。用在 30 分鐘預測時，DP σ=1.1 微調後 4.755 → 4.660，贏過無 DP（5.093）和 naive（4.859）；無 DP 加時段特徵反而變差。
- **`horizon`（第二晚新增）**：預設 1 = 預測下一筆（5 分鐘後）；設 3 = 15 分鐘後、6 = 30 分鐘後。

**`task.py` — 模型、訓練、評估**
- 模型：小型 MLP（12 → 32 → 32 → 1），只有約 1,500 個參數。用 MLP 是因為 Opacus 能直接對它做逐樣本裁剪，比 RNN 單純。
- **殘差設計（本次新增，預設開啟）**：輸出 = 最後一筆車速 + MLP 預測的修正量。模型一開始就等於「猜跟上一筆一樣」，只需學「會變快或變慢多少」。DP 的裁剪會讓學習變慢，這個設計讓 DP 模型在真實資料上的 MAE 從 2.92 降到 2.71。
- `train()`：跑本地訓練並回傳步數（ε 計算需要步數）。損失函數可選 mse（預設）、huber、l1。DP 的 Poisson 取樣偶爾會抽到空批次，也照樣走一步，否則步數會和隱私計算對不上。
- `evaluate()`：算 MAE、RMSE（換回 km/h），**本次新增** naive 基準 MAE（直接猜「下一筆 = 最後一筆」），用來檢查模型有沒有比最笨的方法好。

**`client_app.py` — 每個 VD（client）**
- 每輪：收到伺服器的模型 → 用自己的訓練資料訓練 1 個 epoch → 回傳新參數與指標。
- `use-dp=true` 時用 Opacus 包裝（逐樣本裁剪 C=1.0 + 雜訊 σ + Poisson 取樣）。
- 訓練完順便用自己的測試資料評估剛訓練好的本地模型（`local-mae-kmh`）。
- 評估時：用自己的測試資料算全域模型的 MAE 等，回報給伺服器。
- **個人化微調（第二晚新增，預設開啟）**：最後一輪評估時，各 VD 把最終全域模型在自己的訓練資料上再訓練 `finetune-epochs`（預設 3）個 epoch、學習率 `finetune-lr`（0.05），DP 時一樣加噪，回報微調後的 MAE（`ft-mae-kmh`）和把這幾步也算進去的 ε（`ft-epsilon`）。微調後的模型只在本地用、不上傳。
  為什麼：全域模型是 8 個 VD 的「平均」，常塞車的 10 公里路段和順暢路段特性不同，微調把模型拉回自己的路況。真實資料上 DP σ=1.1 從 2.712 降到 2.669，σ=3（ε<1）從 2.745 降到 2.700。

**`privacy.py` — 跨輪累計 ε（本專案的關鍵修正）**
- 問題：Flower 每一輪都會重建 client，若照 Flower 官方範例在每輪新建 Opacus 的 PrivacyEngine，ε 會歸零，只算到「單輪」的 ε，嚴重低估。
- 做法：每輪把（σ, 取樣率 q, 步數）存進 client 的 `context.state`，每次用全部歷史重算 ε。公式與 Opacus 官方 RDP accountant 相同，並有單元測試互相驗證。

### 5.3 執行與分析

**`scripts/run_experiments.py`（Windows 用）/ `run_experiments.sh`（Linux/Mac）— 一鍵跑實驗**
- 依 manifest 的 VD 數寫入 Flower 設定檔（`scripts/setup_flwr_home.py`，寫在專案內 `.flwr_home/`，不動你的家目錄設定）。
- 依序跑：無 DP 對照組 → 每個 σ 的 DP；**本次新增** `--seeds 1 2 3` 讓每個設定重複跑多個隨機種子，`--client-sigmas 2 4` 跑 client-level DP。
- 最後自動呼叫 `plot_results.py`。
- `--smoke`：用合成資料跑 2 輪，檢查整條流程能不能動。

### 5.4 安全性補強（第四輪，PR #5，依課程講義 IoT 安全）

- **HMAC-SHA256**（`verify-updates=true`，預設）：每個 VD 用自己的金鑰簽上傳的模型更新，簽章包含輪次與 VD 編號，伺服器驗不過就不聚合。為什麼：擋網路上的竄改、冒充和重送。實測 25% 上傳被竄改時，沒驗證全域 2.465 輸 naive，有驗證 2.186，和正常的 2.183 一樣。
- **VD 端數位簽章**（`update-auth='ed25519'`，選用）：VD 用自己的 Ed25519 私鑰簽上傳，伺服器只有公鑰，偽造不了，對應講義的不可否認性、可歸責性；並寫出 `audit.jsonl` 稽核紀錄。準確度和 HMAC 一樣（2.183）。
- **Ed25519 模型簽章**（`sign-models=true`，預設）：伺服器簽全域模型，VD 驗證通過才用，對應講義「假韌體更新」的案例。
- **穩健聚合**（`aggregator=median／trimmed`）：VD 被入侵時它有合法金鑰，HMAC 擋不住。3 個 VD 送惡意更新時 FedAvg 爆到 251，中位數 2.232、截尾平均 2.236，仍贏 naive 8%；沒攻擊時代價只有 +0.002～0.005。入侵增加到 10/32 個 VD 時，截尾平均完全失效（約 8×10⁵），中位數全域 2.469 只略輸 naive、微調後 2.160，另一個選擇是伺服器端裁剪（每個 VD 更新裁到 0.2）：10 個 VD 被入侵時全域 2.395 仍贏 naive，但沒攻擊時就要多付約 0.09（2.269）。平時建議用中位數，預期攻擊者很多時再考慮伺服器端裁剪。裁剪加中位數合用在 10 個 VD 被入侵時最好（2.371）；14/32 個時全域模型都輸 naive，但微調後仍贏（中位數 2.190、裁剪 2.349）。
- **安全聚合**（`secure-agg=true`）：成對遮罩讓伺服器只看得到所有 VD 更新的加總，防「伺服器不可信」。準確度不變（2.183），上傳量 6.1 → 12.3 KB；不能和中位數聚合、client-level DP 同時用，也不容許中途斷線。
- **斷線**（`dropout-rate`，模擬用）：每輪 30% VD 沒回應，全域 2.194，訓練照常完成。
- **壓縮上傳**（`upload-bits`）：把更新隨機捨入成少數位元再上傳，ε 不變。4 位元時每輪 6.1 → 0.79 KB（小 7.8 倍），準確度不變，適合 LPWAN；2 位元開始變差（2.203）。
- **全部防禦一起開**（VD 簽章 + 4 位元 + 中位數 + 伺服器裁剪）：同時有 3 個被入侵 VD、10% 竄改、10% 斷線時，全域 2.295、微調後 2.164，仍贏 naive；沒攻擊時 2.275（代價主要來自裁剪）。256 個 VD 時，沒防禦的 FedAvg 只要 26 個 VD（10%）被入侵就壞掉（約 368）；全部防禦開著、同樣攻擊加 10% 竄改與斷線，全域 2.304（好 8.5%）、微調後 2.199（好 12.7%）。
- **金鑰**：每個 VD 一把隨機金鑰（`keys/vd-<編號>.key`，不進 git），沒有共用主密鑰。第一版從同一個設定值推導金鑰，`security-review` 抓到後改掉。
- 結果與圖見 `進度報告_2026-11-02.md`（32 個 VD、record DP σ1.1、3 seed）。

## 7. 重要設計取捨（報告時要講清楚）

1. **record-level DP**：預設保護的是「單筆 5 分鐘紀錄」，不是整個 VD。相鄰時間的資料高度相關，解讀 ε 時要註明。保護整個 VD 的 client-level DP 可以選用，但 8 個 VD 時代價太大。
2. **ε 只涵蓋上傳的模型參數**：client 另外回報的訓練 loss、樣本數、測試 MAE 沒有加雜訊，屬研究用診斷資訊。
3. **固定亂數種子**：為了可重現，沒開 Opacus 的 `secure_mode`；正式部署需要開。
4. **為什麼 σ=0.8～1.5 的 MAE 幾乎一樣**：雜訊有加（ε 不同就是證據），但 σ 在這個範圍時雜訊對模型的影響很小；舊版 DP 變差主要是「裁剪」讓學習變慢。σ 再加大就看得出差別：σ=2/3/5 的全域模型 MAE 為 2.725/2.745/2.833（第二晚 Flower）。
5. **為什麼用殘差模型、學習率 0.2**：真實資料 3 個 seed 調參的結果；其他嘗試（更大學習率、不同 C、更大模型、30 輪）都沒有更好。
6. **個人化模型 vs 全域模型**：微調後的模型只在各 VD 本地使用。若要「對外發布一個模型」，那是全域模型，報告時要用全域模型的 MAE 與 ε；個人化的數字要標明是本地模型。
7. **成員推論攻擊實測**：攻擊 AUC 約 0.52（0.5 = 亂猜），有無 DP 都一樣低，表示這個攻擊對本模型無效，無法用來證明 DP 有沒有作用；DP 的保證以 ε 為準。
8. **系統在物聯網架構中的位置**：VD 是感知層、client 是邊緣運算、Flower 是網路層、伺服器是雲端聚合、預測是 AI 應用（對照課程 Lecture 2）。
9. **資料長度（已改用 4 週）**：原本只有兩週（2024-03-04～03-17），測試期間 71% 是週末，驗證集代表不了測試集。第三輪改用 **4 週資料**（03-04～03-31，`real-vd/processed_28d/`，GitHub 分支 `data/vd-28d`），測試期間 3/26～3/31、週末 36%。4 週資料上時段特徵讓 DP σ=1.1 微調後 2.719 → 2.684（5/5 seed，ε 2.54），σ=3 2.777 → 2.749（ε 0.64），無 DP 2.736 → 2.693；30 分鐘預測 DP σ=1.1 5.053 → 4.864、無 DP 5.390 → 4.995（naive 5.471）；「昨天同一時刻車速」仍沒幫助。報告以 4 週資料為主、兩週為補充。仍只有一個月、8 個 VD。

## 8. 常見問題

- **`WinError 126 ... shm.dll`**：裝 Microsoft Visual C++ Redistributable（https://aka.ms/vs/17/release/vc_redist.x64.exe），或跑 `python scripts/fix_torch_windows.py`。
- **卡住不動 / client 數不一致錯誤**：請用 `run_experiments.py` 執行，它會自動把 Flower 設定的 client 數對齊 manifest。
- **想換參數**：`python scripts/run_experiments.py --extra "learning-rate=0.1 local-epochs=2"`。
- **想關掉個人化微調**：`--extra "finetune-epochs=0"`。
- **想關掉時段特徵**（PR #3 合併後）：把 `pyproject.toml` 的 `calendar` 設成空字串 `""`。
- **想用特定 VD**：`python scripts/preprocess_vd.py --vd-ids <VDID> <VDID> ...`。
